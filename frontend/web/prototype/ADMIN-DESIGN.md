# 智语同航 · 超管端设计文档

> 状态：设计中（v0.1）
> 关联原型：`admin-console.html`（同一目录，双击打开）

---

## 一、定位

**超管 = 平台运营方，负责系统整体管理。**

核心约束：**超管不使用任何业务功能**——不生成作文、不批阅、不用实时转译、不生成单词素材。
超管只做「管理业务」：看数据、管用户、管内容、管配置、处理反馈。

超管账号 `tenant_id = 0`（平台级），超然于租户之上。现阶段只有一个租户。

---

## 二、数据模型

### 2.1 用户类型（已定）

```sql
ALTER TABLE sys_user
  ADD COLUMN user_type VARCHAR(20) NOT NULL DEFAULT 'student'
  COMMENT '用户类型: student 学生 / teacher 老师 / admin 超管';
```

```java
public enum UserTypeEnum {
    STUDENT("student", "学生"),
    TEACHER("teacher", "老师"),
    ADMIN   ("admin",   "超管");
}
```

| 类型 | 业务功能 | 课堂授课 | 超管后台 |
|---|---|---|---|
| `student` | ✅ 基础功能 | ❌ | ❌ |
| `teacher` | ✅ 基础功能 | ✅ | ❌ |
| `admin`   | ❌ **禁用** | ❌ | ✅ |

> 命名说明：用 `type`（身份分类）而非 `role`（权限集合）。三者互斥，一个人只有一种身份。

### 2.2 注册（已定）

两个独立接口，`user_type` 由**后端硬编码**，前端传什么都不影响：

```
POST /sys/user/register/student  → user_type = STUDENT
POST /sys/user/register/teacher  → user_type = TEACHER
```

内部共用一个 Service，只是传入不同枚举：
```java
public Long register(RegisterDTO dto, UserTypeEnum type) { ... }
```

### 2.3 超管来源（已定）

**不开放注册**，防止任何人注册成超管：

1. 系统初始化时 SQL 内置第一个超管
2. 之后由现有超管在「用户管理」中分配

「设为超管」为**高危操作**：二次确认 + 审计日志。

### 2.4 租户（已定：现阶段不加）

不加 `tenant_id`。理由：

- 现在没有机构概念，加了只能全填 1，是无意义字段
- 真正的隔离单元是**课堂**（`classroom_id`）
- 将来加的成本很低（一条 UPDATE）

**将来分租户时一次加齐**：`tenant` 表 + `user.tenant_id` + `classroom.tenant_id` + 查询拦截器。

### 2.5 课堂（后续，非本期）

课堂是租户内的「小租户」，靠课堂码进出。这是 C→B 的演变中间态。

```
tenant（现在只有 1 个）
  └─ classroom（课堂码进出，真正的数据隔离单元）
       ├─ teacher（创建者）
       └─ student（成员）
```

角色挂在**课堂成员关系**上（不是用户本身）——同一个人在 A 课堂是老师、在 B 课堂可以是学生。

## 三、权限设计

### 3.1 原则

**前端按 type 隐藏入口只是体验优化，不是安全控制。** 后端必须每个接口独立校验。

### 3.2 实现：注解 + 拦截器

```java
@RequireType(UserTypeEnum.TEACHER)      // 仅老师
@RequireType(UserTypeEnum.ADMIN)        // 仅超管
@RequireType({STUDENT, TEACHER})        // 学生和老师（排除超管）
```

- 业务接口标注 `@RequireType({STUDENT, TEACHER})` → **超管被自动挡在业务功能外**
- 管理接口标注 `@RequireType(ADMIN)` → 仅超管可访问

做成注解而非手写 if，避免新接口漏判。

### 3.3 目录约定

- 业务接口：`/api/reading/**`、`/api/writing/**`、`/api/asr/**` → 排除 admin
- 管理接口：`/api/admin/**` → 仅 admin

## 四、功能模块

### 4.1 运营数据看板

回答四个问题：有多少人在用 / 用得勤不勤 / 都在用什么 / 有没有问题。

**核心指标（6 个）**

| 指标 | 数据来源 |
|---|---|
| 总用户数 | `sys_user` count |
| 今日活跃 DAU | `lastLoginTime` 或业务表去重 |
| 月活跃 MAU | 近 30 天 |
| 本月新增 | `sys_user.create_time` |
| 本月使用次数 | 三张业务表 count |
| 失败率 | 失败表 / 总调用 |

**趋势分析（三视角切换）**

- 用户增长：每日新增柱状 + 累计折线
- 活跃度：DAU + MAU 双线 + DAU/MAU 粘性
- 功能使用：出题 / 批阅 / 单词 三折线

**其他**

- 功能使用分布（出题/批阅/单词/转译）
- 用户分层：重度≥20次 / 中度5-19 / 轻度1-4 / 沉默未用
- 最近失败（实时）

### 4.2 用户管理

| 能力 | 说明 |
|---|---|
| 列表 | 搜索（账号/昵称/手机/邮箱）+ 类型筛选 + 状态筛选 + 分页 |
| 详情 | 基本信息、使用统计、模型偏好、API Key 数量 |
| 禁用 / 启用 | 不做真删除（业务数据关联），只禁用 |
| 改类型 | 学生 ↔ 老师 |
| 设为超管 | ⚠️ 高危，二次确认 + 留痕 |
| 重置密码 | — |

**不提供**：删除用户（会导致业务数据悬空）

### 4.3 教学数据（只读）

四个 Tab：作文出题 / 作文批阅 / 单词素材 / 实时转译

- 按时间、用户、状态筛选
- 失败记录可展开看错误码与错误信息
- **只读**，不提供重跑 / 删除

> ⚠️ 实时转译当前**不落库**，该 Tab 无数据。需新建转译记录表 + 在 `AudioWebSocketHandler` 埋点。

### 4.4 AI 用量

BYOK（用户自带 Key）模式下**不做成本统计**，费用由用户自担。

| 模块 | 数据来源 |
|---|---|
| 本月调用量 | 业务表 `create_time` |
| 按模型拆分 | 业务表 `model_name` ✅ 已有 |
| Top 10 用户 | 业务表按 user 聚合 |
| 按厂商分布 | 业务表 `provider` ✅ 已有 |
| 失败日志 | 4 张失败表 |

> 所有业务表均已记录 `provider` + `model_name`，**无需额外埋点**。

### 4.5 反馈管理

- 三个状态 Tab：待处理 / 已回复 / 已关闭
- 查看反馈正文、回复、标记已解决
- 字段来自现有 `sys_user_feedback`

### 4.6 系统配置

需新建配置表（或单表 + JSON 配置）：

| 配置项 | 说明 |
|---|---|
| ASR 默认模型 | 新用户默认使用 |
| 翻译默认模型 | 纠错随翻译，不单独配 |
| 功能开关 | 开放注册 / 实时转译 / 作文批阅 / 图片批阅（灰度）/ 单词配图 / 试用模式 |
| 公告管理 | 新建 / 编辑 / 发布 / 下线 |

## 五、导航：双模式

### 经典模式
侧边栏分组 → 页面

```
管理控制台：看板 / 用户管理 / 教学数据
运营：AI 用量 / 反馈管理
系统：系统配置
```

### 星空模式（试点）
三级导航，与经典模式一一映射：

```
📊 看板（中心直达）
   └ 总览 / 用户增长 / 活跃度 / 功能使用
🏛 管理控制台
   ├ 👥 用户管理 → 用户列表 / 用户分层 / 新增趋势
   └ 📚 教学数据 → 作文出题 / 作文批阅 / 单词素材 / 实时转译
🚀 运营
   ├ ⚡ AI 用量 → 调用量 / 模型分布 / 厂商分布 / 失败日志
   └ 💬 反馈管理 → 待处理 / 已回复 / 已关闭
🛠 系统
   └ ⚙️ 系统配置 → 模型配置 / 功能开关 / 公告管理
```

- 一级 = 分组（星球），二级 = 模块（星球），三级 = 页面内 Tab（不再是星球）
- 进入内容后**不显示经典侧边栏**，页面只有该模块本身
- 轨道容量：**每轨道最多 6 颗**，超出自动开新轨道（半径 +130px，转速递减）
- 右上角切换，偏好存 `localStorage`

## 七、待确认

3. **优先级**——第一版先做哪块？
