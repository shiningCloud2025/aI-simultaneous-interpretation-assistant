# 实时翻译+纠错 技术方案

## 背景

智慧英语课堂的核心业务是**实时语音转译**：用户通过麦克风/扬声器输入音频，后端通过 ASR 语音识别得到原文，再调用 LLM 进行翻译和纠错，最终在前端实时展示。

## 核心挑战

### 问题 1：ASR 流式推送与翻译的并发冲突

**现象**：ASR 是流式的，每几百毫秒推送一个片段（"你" → "你好" → "你好机器学习"）。如果每个片段都触发一次翻译，会出现请求堆叠和覆盖问题——上一个翻译还没跑完，下一个又触发了。

**根因**：LLM 翻译速度（~500ms-1s）跟不上 ASR 推送速度（~100-300ms）。

**解决方案**：增量翻译 + 等上一个完成再取最新

后端维护一个 TranslationSession，管理以下状态：

- `latestText`：当前最新的 ASR 原文
- `lastTranslatedText`：上次已翻译的原文

```
流程：
1. ASR 流式推送 → 更新 latestText（不触发翻译）
2. 定期检查（每 200ms）：
   - 如果当前有翻译在进行 → 跳过
   - 如果当前没有翻译 → 取 latestText，计算增量
3. 增量 = latestText 去掉 lastTranslatedText 前缀
4. 将增量发给 TranslatorAgent（Agent 保持会话上下文）
5. 翻译完成 → 更新 lastTranslatedText，流式推送译文到前端
```

**效果**：
- 不堆叠请求，一次只跑一个翻译
- 不重翻已翻过的内容，省 token
- Agent 保持上下文，翻译连贯

---

### 问题 2：原文纠错与译文纠错的竞态问题

**现象**：如果原文纠错和译文纠错分开跑（两个独立 Agent），原文纠错后发现原文变了，但译文是基于旧原文翻的，导致译文过时。

```
t1: 原文"极其学习" → 翻译 → 译文"Extremely Learning"
t2: 纠错原文 → "机器学习"（原文变了！）
t3: 纠错译文"Extremely Learning" → 但原文已经变成了"机器学习"，纠错失去意义
```

**解决方案**：一个 CorrectorAgent 同时纠错原文+译文

CorrectorAgent 接收"原文 + 译文"作为输入，输出"修正后原文 + 修正后译文"（或"无需修正"）。

System Prompt 示例：
```
你是翻译纠错助手。你会收到一段原文和对应的译文。
请检查：
1. 原文是否有 ASR 识别错误（同音词、错字、漏字）
2. 译文是否准确、通顺、术语是否正确
如果有问题，请同时返回修正后的原文和译文。如果没问题，回复"无需修正"。
```

**效果**：原文和译文的纠错在同一轮 LLM 调用中完成，不存在竞态。

---

### 问题 3：多 Agent 串行导致的延迟问题

**现象**：如果走"纠错 → 翻译 → 润色"的串行管线，用户需要等 3 次 LLM 调用才能看到结果，延迟叠加到 3-5 秒，体验不可接受。

**解决方案**：翻译走主链路，纠错走后台异步

```
实时场景：
  ASR → TranslatorAgent（主链路，低延迟）→ 流式译文 → 前端
         ↓
  CorrectorAgent（后台异步，不阻塞）→ 修正结果 → 前端覆盖更新

静态场景：
  ASR全文 → CorrectorAgent → TranslatorAgent → 最终译文（质量优先，延迟可接受）
```

**效果**：
- 用户先看到译文（~500ms-1s），纠错结果稍后悄悄覆盖
- 延迟体验接近单 Agent，质量不妥协

## 最终架构

### Agent 清单

| Agent | 职责 | 输入 | 输出 | 触发时机 |
|-------|------|------|------|---------|
| **TranslatorAgent** | 翻译 | 原文增量 | 译文增量 | 实时：句子稳定后 |
| **CorrectorAgent** | 纠错原文+译文 | 原文 + 译文 | 修正后原文 + 译文 | 后台异步 |

### 实时场景数据流

```
用户说话
  ↓
音频流 → WebSocket → ASR引擎 → 流式原文片段
  ↓                              ↓
前端实时显示原文          TranslationSession
                            ↓
                     TranslatorAgent（增量翻译）
                            ↓
                     流式译文 → WebSocket → 前端
                            ↓
                     CorrectorAgent（后台异步）
                            ↓
                     修正结果 → WebSocket → 前端覆盖
```

### 前端消息类型

```json
// 原文（ASR 直出）
{ "type": "source", "text": "你好机器学习", "seq": 1 }

// 译文（翻译 Agent 出）
{ "type": "translation", "text": "Hello Machine Learning", "seq": 1 }

// 纠错修正（CorrectorAgent 出，覆盖前面）
{ "type": "correction", "sourceText": "你好，机器学习", "transText": "Hello, Machine Learning", "seq": 1 }
```

## 技术选型

- **Agent 框架**：AgentScope Java 2.0（`agentscope-core`，ReActAgent）
- **响应式编程**：Project Reactor（AgentScope 内置支持）
- **模型接入**：OpenAI 兼容协议（DeepSeek / 阿里云 / OpenAI 等）
- **API Key**：从 `sys_user_api_key` 表读取用户配置
- **术语库**：从 `sys_user_term_entry` 表读取，注入 TranslatorAgent 的 system prompt
